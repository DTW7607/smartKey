# 智键首版需求审查与建议

日期：2026-09-07。状态：基于用户新范围的需求建议，尚未进入实现。取代早期方案中冲突的首版范围与快速操作指标。

> 最新调整：脚本内容的预览与编辑统一交给系统默认应用，智键不内置源码预览或编辑器。具体开发顺序与验收以 [首版开发计划](smartKey-v1-implementation-plan.md) 为准。

本次是尚未实现的设置面板与动作功能的需求审查，不是已有界面的视觉验收。平台规范来自 Apple 官方资料，代码判断来自当前仓库；没有启动应用或进行硬件/权限实测。

## 1. 已明确的首版范围

- 智键服务低频快捷操作，无需连续击键或快速连击体验。
- 动作执行采用统一接口，支持未来扩展宏、打开应用等类型；首版只实现键盘、多媒体和脚本。
- 每个动作有不超过 8 个字的名称，触发气泡显示动作名称。
- 设置面板采用原生 macOS Liquid Glass 设计语言，左侧导航为通用、动作绑定、脚本管理。
- 单击、双击、长按分别选择一个动作或“无”；选择“无”不弹该事件的气泡。
- 双击识别由双击绑定自动控制；无绑定则关闭，有绑定则开启。
- 脚本可拖入、导入、编辑、重命名、导出，具备名称、预览、说明，并支持试运行。

建议把首版产品目标收敛为：**用户能在一个设置窗口中完成“选动作或准备脚本 → 绑定手势 → 按下实体键 → 看见动作名称与执行状态”。**

## 2. 统一接口：统一执行契约，动作各自实现

不要把键盘、多媒体、打开应用都转成 shell 命令。它们应共享执行契约，但分别使用合适的原生实现。脚本是其中一种执行器。

建议拆分四个对象：

| 对象 | 责任 |
|---|---|
| ActionDefinition | 可持久化的动作实例：稳定 ID、类型 ID、短名称或名称来源、版本、参数 |
| ActionProvider | 一种动作类型的校验、能力说明和执行入口 |
| ActionRegistry | 按类型 ID 注册与查找 Provider；首版注册 keyboard、media、script |
| ActionDispatcher | 根据绑定找到动作，执行统一的冷却、权限检查、运行管理与反馈策略 |

接口概念示意，具体 Swift 类型在实现设计时确定：

```text
ActionProvider
  typeID
  parameterVersion
  capabilities(definition) -> 需要的权限、可取消性、结果是否可验证
  validate(definition) -> 参数/依赖问题
  start(definition, context) -> ExecutionHandle

ExecutionHandle
  executionID
  stateUpdates -> 已提交 / 运行中 / 成功 / 失败 / 取消 / 超时
  cancel() -> 尝试取消

ExecutionContext
  来源（物理手势/试运行）
  触发时间、目标应用快照、配置版本、动作名称快照
```

同步动作也返回统一的完成结果，异步脚本则持续更新状态。“已发送键盘指令”与“已验证目标状态”要在结果中区分。执行器不创建气泡、不依赖 HID、不读设置窗口，也不自行决定冷却。

“无”保存为绑定为空，不创建假执行器。未来宏 Provider 可以调用同一动作服务依次运行子动作；那时再增加循环引用检测、逐步失败和取消规则。打开应用只需新增 Provider 和对应参数编辑器，不改手势识别。

二次开发首版建议限定为**源码层扩展**：提供注册示例、参数版本规则、结果约定和一个最小示例 Provider。未知类型保留配置、显示“当前版本不支持”，不崩溃、不静默改为别的动作。外部动态插件、热加载二进制与插件市场不属于这一接口的首版承诺。

## 3. 低频操作与气泡名称

### 3.1 保留冷却，取消快速连击指标

保留当前按压动效与低频触发节奏，取消上一版“每秒 5 次”“连续调音量不丢”等验收项。无须做连发、事件积压或高速队列。

仍建议把冷却判定放到 Dispatcher 的触发策略中：物理手势先解析绑定，再判定是否接受；接受后开始执行并展示气泡。动作执行器本身不读取气泡动画。首版可沿用现有冷却计算和时长，无需新增独立的冷却设置。

绑定为空不执行、不弹气泡，也不开始新的动作冷却。冷却期内的物理手势忽略、不排队，原始按压缩罩可继续响应。气泡显示失败不应取消已接受的动作。

试运行不受物理手势的冷却约束，但使用相同的执行器、参数校验、权限、脚本防重入和超时策略。长脚本的“正在运行”不靠延长物理手势冷却实现。

### 3.2 名称规则

建议将“不超过 8 个字”定义为：**去除首尾空白后 1–8 个用户可见字符，中文、英文字母、数字、标点均计数，禁止换行和控制字符。** 实现按用户可见字符计数，不按 UTF-8 字节数；兼顾输入法组合输入，不在拼音输入途中粗暴截断。

- 键盘/媒体动作自动生成短名称，可在绑定编辑时修改，例如“保存文档”“播放暂停”“音量增加”。
- 脚本名称也限制为 1–8 字，作为该脚本动作的显示名称；长说明放在说明字段。首版不增加独立的“绑定别名”，减少双重命名。
- 脚本重命名后，其所有绑定同步显示新名称；运行中的气泡与记录保留触发时的名称快照。
- 同名脚本建议在库内禁止，复制/导入时让用户确认新名称；内部引用始终使用 ID，不使用名称或文件名。
- 输入框显示字符计数，超长时提示并阻止保存，不静默截断用户命名。导入长文件名时可提供短名称建议，必须能编辑。

气泡主文本固定为动作名称，状态用图标/进度指示表达，例如“部署项目”旁出现运行、完成或失败图标。不要把 stdout 放进气泡，也不要把“运行成功”追加到短名称里导致超长。完整状态通过无障碍标签和设置内运行结果提供；不能仅用颜色区分失败。

触发后的气泡表示本次动作已被接受，不等于已执行成功。键盘/媒体无法读回效果时显示“已发送”状态；脚本运行超过气泡时长后气泡正常收回，完成时可再短暂显示一次同名结果气泡，详情留在脚本管理。

## 4. 动作绑定与 conf 的一致性

### 4.1 绑定页

右侧按“单击 / 双击 / 长按”排列三行或三张紧凑分组，不增加多方案层。每项展示动作类型、短名称、关键参数、编辑与测试入口。

选择菜单分组为：无、键盘功能、多媒体功能、执行脚本。脚本子菜单列出脚本库名称，底部提供“管理脚本…”；脚本库为空时显示“添加脚本…”。取消选择/编辑保留原绑定。

选定键盘或媒体类型后，配置其参数并完成保存才算绑定；尚未填完的草稿不提前启用手势。已有动作改为“无”可以立即保存，并提供短暂撤销入口。

### 4.2 双击自动控制

```text
doubleClickEnabled = 双击是否具有已保存且非空的动作绑定
```

当前 conf 的字段名是 `doubleClickEnabled`，解析器接受数字，因此继续写 `0/1` 表达 false/true；直接写 `false/true` 需要额外修改解析规则，不建议为此改变文件格式。

| 操作/状态 | 建议结果 |
|---|---|
| 双击选择“无” | 保存空绑定，运行时关闭双击识别，conf 写 0；单击松开即判定 |
| 双击保存有效动作 | 启用识别，conf 写 1；页面提示“单击将等待双击判定”及实际窗口时长 |
| 双击开始编辑但取消 | 保持旧绑定与旧开关 |
| 已绑定脚本暂时无法执行/权限被撤销 | 保留绑定和双击识别，显示不可执行原因；不要暗中改变手势语义 |
| 三种手势全选“无” | 合法状态；显示“尚未绑定动作”，所有动作气泡停止 |
| 重启或迁移 | 从已保存绑定推导开关，校验并同步 conf |

建议把此字段标注为“由动作绑定自动管理”，通用页不再设置独立双击开关。手动改 conf 与绑定冲突时，以绑定为准纠正字段，并在设置中显示一次非弹窗说明；其他手势时长和外观配置保持原有热更新。

这是对既有 conf 语义的一项有意调整，须写入升级说明。若必须保留用户手动开关的绝对优先权，就会出现“已有双击绑定但不启用”的第三种状态，与本轮要求不一致，首版不建议采用。

绑定保存与推导字段由同一配置服务处理。界面仅在持久化成功后提示已保存；运行时整体替换快照，不应用半份配置。由于动作文件和 conf 是两个文件，应采用单一权威绑定记录加启动时修复派生字段的策略；写入异常需保留可恢复记录并提示，不能声称两个独立文件天然具有原子事务。只更新目标字段、保留其他用户值，抑制文件监听产生的自我写入循环。

### 4.3 “无”容易遗漏的边界

建议长按为“无”时仍识别并消费长按，松开后不补发单击；否则用户按住不放，最后可能误触单击动作。单击为“无”时也保留对双击和长按的正常识别。双击为“无”按明确要求关闭识别，所以连续两次短按将按两次单击处理，第二次若落在既有冷却期则忽略。

“不弹对应弹窗”指动作气泡；按下/松开的黑色缩罩、设备配置提示不随单个空绑定关闭。三项均为空时建议继续保持现有设备模式与音频守卫，不自动释放线控导致它突然恢复系统媒体行为。

绑定变化对下一个完整手势生效；手势中途改绑定不改变已经开始的按压。正在运行的脚本不因清空绑定自动终止，用户仍可在脚本管理中停止它。

## 5. 设置窗口与 Liquid Glass

### 5.1 信息架构

| 左侧导航 | 右侧内容 |
|---|---|
| 通用 | 当前设备状态/重新配置、登录启动、暂停动作、手势时长、必要权限入口；双击显示只读自动状态 |
| 动作绑定 | 三个手势的绑定、短名称、参数与测试；不混入代码编辑器 |
| 脚本管理 | 脚本列表、元信息、默认应用打开入口、试运行结果 |

通过菜单栏“设置…”打开可聚焦、可缩放的原生窗口，使用标准标题栏、关闭行为与设置快捷键。不要复用提示气泡承载设置表单。关闭设置不退出菜单栏程序；再次打开恢复上次页面。

脚本管理可采用“应用导航 + 脚本列表 + 元信息详情”的三栏结构。脚本列表属于内容列表，不重复做第二层浮动玻璃导航；窄窗口允许收起全局侧栏，确保表单与运行结果仍可用。

### 5.2 玻璃与动效建议

Apple 将 Liquid Glass 用于控件与导航层；官方采用指南也指出过度使用自定义玻璃控件会分散对内容的注意力。因此建议积极使用原生玻璃侧栏、工具栏、重要操作控件和状态转换；表单与日志使用清晰稳定的内容背景。[Apple HIG：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)；[Apple：Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

优先采用系统侧栏、列表、分组表单、菜单、sheet 和原生按钮；使用公开 Liquid Glass API 补充确有必要的自定义控件，避免多层玻璃叠加。脚本管理的列表/详情分层也符合 Apple 对较深信息结构采用分栏的建议。[Apple HIG：Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)

推荐动效：侧栏选中迁移、绑定参数展开收起、拖入区域高亮、试运行按钮到停止状态的变化、同一动作的运行/结果状态过渡。避免背景持续形变或每次输入都触发材质运动；动效表达状态变化，不增加输入和执行等待。

“严格支持 Apple 规范”应转为可验收条件：浅色/深色、系统 Liquid Glass 偏好、减少透明度、减少动态效果、增加对比度、VoiceOver、全键盘操作、焦点可见和不同窗口尺寸。优先让系统组件自然适配，定制效果需补齐降级路径。[Apple：Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

### 5.3 当前代码需要纠正的规范差距

`Sources/smartKeyPopup/GlassBubble.swift:31` 通过 selector 动态调用 `set_adaptiveAppearance:`、`set_scrimState:`、`set_contentLensing:`、`set_variant:` 等未公开实现细节。建议新设置面板只用公开 API；如果严格遵循规范覆盖整个产品，则把旧气泡迁移到公开 API 的工作也纳入首版，并单独对照验收外观变化。

这属于源码层面的风险发现，尚未对真实窗口的对比度、动效或无障碍行为完成视觉验收；在开发前不宣称现有或拟议界面已全面符合 HIG。

## 6. 首版动作目录

| 类型 | 建议首版范围 | 关键限定 |
|---|---|---|
| 键盘 | 一个普通按键或一个组合键；含方向键、功能键及常用修饰键 | 显式录制模式；不含文本片段、按键序列、按住重复或录制宏 |
| 多媒体 | 播放/暂停、上一首、下一首、音量增加/减少、输出静音切换 | 先验证系统路由与设备能力；不支持时给出原因；不含麦克风静音 |
| 脚本 | 执行脚本库中一个已保存脚本版本 | 后台非交互运行；调用统一执行接口 |

音量步长建议默认 5 个百分点，可在动作参数中调整。方向、功能键与媒体键在界面分类清晰，避免用“键盘功能”承诺所有系统动作。首版不包含打开应用、宏或快捷指令专用界面；未来通过 Provider 扩展。

键盘测试使用倒计时提示用户切回目标应用；物理触发时记录目标应用，并在实际发送前验证。权限缺失或目标已变化时不悄悄发往设置窗口。按键完整释放，退出、取消或失联时不遗留模拟修饰键。

## 7. 脚本管理：脚本库、外部打开和试运行

### 7.1 采用应用托管的脚本库

拖入和导入均复制到应用管理目录，后续编辑修改副本，不改用户原文件。内部存储使用稳定 ID 与版本，名称和导出文件名不作为身份；原文件移动或删除不破坏绑定。外部文件实时链接模式后置。

首版建议支持 Shell 文本脚本，可选 `/bin/zsh` 或 `/bin/bash`；Python 等自定义解释器留作选配，除非已经确定首版有此场景。脚本可自行调用外部工具，但依赖缺失应明确报错，不自动安装。

每个脚本建议包含：

| 信息 | 建议表现 |
|---|---|
| 名称 | 必填，1–8 个可见字符；重命名不会断开已有绑定 |
| 说明 | 可选多行文本，说明用途、依赖和副作用；首版不支持富文本 |
| 内容 | 通过“用默认应用打开…”在系统关联应用中预览或编辑，不内置代码编辑 |
| 列表摘要 | 显示说明、类型和文件状态；不显示源码预览 |
| 运行设置 | 解释器、工作目录、超时；环境变量放入可折叠高级区域 |
| 使用情况 | 显示被单击/双击/长按哪些项目引用 |
| 运行结果 | 最近状态、时间、耗时、退出码、stdout/stderr、停止入口 |

预览与编辑合并成“用默认应用打开…”入口；智键只维护元信息和执行结果，不判断外部应用是否支持编辑，也不修改系统文件关联。

### 7.2 生命周期与保存规则

- 新建：生成脚本文件与元信息，通过默认应用继续编辑。
- 导入/拖入：展示名称、解释器、说明和文件信息，需要查看内容时通过默认应用打开；导入不自动运行、不自动绑定。首版可先单文件导入，批量导入后置。
- 编辑：默认应用打开脚本库内的副本；内容由外部应用保存，智键监听变化并刷新状态。
- 保存：智键仅保存名称、说明和运行参数；不维护源码草稿。试运行与物理触发读取最新磁盘内容，外部未保存修改不生效。
- 重命名：按稳定 ID 更新，所有引用跟随；其他正在运行的执行使用旧快照。
- 复制：新增副本及新 ID，方便试验；原绑定不变。
- 删除：未被绑定且未运行时可删除并支持撤销；被绑定时展示引用清单，用户选择“解除绑定并删除”后统一处理，包含双击开关联动；运行中需先停止或等待结束。
- 导出：提供“导出脚本文件”与“导出智键脚本包”。前者只包含脚本，后者保存名称、说明、解释器与内容；建议脚本包采用有版本的单个 JSON 文档，首版不打包任意附件、不导出敏感环境变量。导出的是已保存版本。

脚本包首版不是多文件项目包。需要相邻资源、项目目录或第三方依赖的脚本，应设置工作目录并在说明中列出依赖；导出不意味着依赖被一并打包。

### 7.3 试运行与实体键执行保持一致

按钮固定为“试运行”，与物理触发共用最新磁盘内容及执行参数。每次运行读取内容并固定本次快照；外部后续保存只影响下一次运行。无法读取、文件消失或检测到读取期间被修改时，提示刷新/重试，不静默运行旧缓存。外部应用未保存的草稿无法获取，界面提示“运行磁盘上已保存的脚本”。

建议首版后台非交互执行，配置解释器与工作目录；不假设 GUI 的 PATH 等同于用户终端。标准输入关闭，超时默认 30 秒、可调整，停止按钮结束受管进程与可管理子进程；无法保证停止已主动脱离管理的进程或撤销脚本副作用。

按低频定位，**首版最多同时运行一个脚本**足够；正在运行时再次试运行或触发其他脚本，明确提示“已有脚本运行中”，不排队、不自动重跑。键盘和媒体动作仍可按其触发策略运行，不被脚本占用主线程。

stdout/stderr 异步读取，显示可截断的大输出和退出码，不能因管道堵塞卡住应用。建议每路最多保留 256 KiB，超出继续排空并提示截断；详细输出默认只保留本次会话，不记录敏感环境变量。成功以进程报告的退出码为依据，不推断外部部署/提交等业务结果。

首版运行当前用户受信任脚本，不自动提权、不保存管理员密码、不打开外部终端；如果交互式终端是明确目标，应单独纳入范围，不能与后台模式混为一谈。

## 8. 必须随功能交付的边界

| 情况 | 建议规则 |
|---|---|
| 权限不足 | 显示具体权限与入口，拒绝后其他动作可继续工作 |
| 用户暂停动作 | 停止新物理触发；保留设备模式和音频守卫；试运行由明确按钮单独发起 |
| 拔出/锁屏/休眠 | 清理未完成手势、不补发旧事件；正在运行脚本保留状态与超时策略 |
| 退出时有脚本运行 | 提供取消退出或停止任务后退出，不隐瞒仍有任务 |
| 参数/配置损坏 | 使用上一次有效配置并说明问题；不意外改绑 |
| 取消/超时 | 不自动重试；停止的是受管执行，不承诺回滚外部副作用 |
| 设备设置窗口 | 沿用既有设备配置规则，新的动作设置不绕过 HID 与合法音频输出检查 |

## 9. 首版验收与实现顺序

验收围绕低频操作的确定性，而不是吞吐量：

1. 为三种 Provider 分别配置动作，重启后仍正确；同一已接受手势只启动一次。
2. 名称的中文、英文、输入法组合、空白、超长均正确校验；气泡显示保存后的短名与真实状态。
3. 三种手势选择“无”后不弹对应气泡；长按为空时松开不误发单击。
4. 双击绑定增加/删除、启动恢复、conf 手动冲突、写入失败都保持可解释的一致性；关闭双击后单击不再等待双击窗口。
5. 拖入→默认应用打开→外部保存→自动刷新→试运行→绑定→物理触发→重命名→导出→重新导入完整可用；导入来源文件不被修改。
6. 被引用脚本删除有引用处理；解除最后一个双击绑定后自动写 0；正在运行的版本不被编辑覆盖。
7. 缺权限、脚本失败/超时/大输出/重复运行、失联与退出都能恢复，不卡 UI、不残留模拟按键。
8. 公共 Liquid Glass API、标准窗口、浅深色和系统无障碍选项通过真实界面验收；不能仅凭设计图或截图宣称全面符合规范。
9. 新增一个示例 Provider 无需修改手势与气泡代码，统一接口不依赖设置界面或 HID。

推荐顺序：统一动作模型与配置权威关系 → 三类执行器与脚本库 → 设置导航与绑定 → 外部打开/刷新/试运行 → 气泡状态与名称 → 平台、权限与真实硬件验收。媒体兼容性与公开玻璃效果应在前段做小范围技术验证。

## 10. 建议补充确认的产品默认值

以下均为本轮审查建议，不冒充用户已批准的细节：

| 决策项 | 推荐默认 |
|---|---|
| 8 字命名 | 脚本名同时作为动作名；键盘/媒体名称可修改；首版无绑定别名 |
| 双击配置权威 | 绑定是唯一来源，conf 字段作为自动管理的派生值 |
| 低频冷却 | 保留现有节奏，移到统一分发策略，不做高速队列 |
| 长按为空 | 消费长按，松开不补单击 |
| 脚本保存 | 应用托管副本；内容在默认应用保存；执行时读取最新磁盘版本 |
| 解释器 | 首版 Shell（zsh/bash）；自定义解释器后置 |
| 脚本运行 | 后台非交互；全局最多一个脚本运行 |
| 规范范围 | 新设置面板只用公开 API；严格规范若覆盖全产品，同时迁移旧气泡的私有调用 |

建议下一步围绕这八项默认值冻结首版规则，然后制定设置面板各页面的状态稿与统一动作接口设计。
