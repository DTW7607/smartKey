# 使用与配置详解

返回 [项目首页](../README.md)。以下说明对应当前实现；开发过程中的验收记录另见 [首版验证记录](v1-validation.md)。

内置 3.5mm 智键的 macOS 菜单栏程序：为单击、双击和长按绑定键盘、多媒体、脚本或快捷指令动作，触发时用玻璃气泡显示动作名称，按下时右下角出现按压缩罩。需要 macOS 26。

开发运行：

```bash
swift run smartKey
```

安装到 `/Applications`（release 打包、本机 ad-hoc 签名、注册登录项并启动）：

```bash
./scripts/install-app.sh
```

只打包、不安装或启动：`./scripts/build-app.sh`，产物位于 `.build/release-app/smartKey.app`。

App 图标使用黑白圆环与圆点，资源位于 `packaging/AppIcon.icns`，菜单栏使用随系统外观适配的单色符号。修改图标几何后，运行 `swift scripts/generate-app-icon.swift` 重新生成 SVG、1024 像素 PNG 和包含各尺寸的 ICNS，再重新打包或安装。

## 设置与动作

从菜单栏打开「设置…」（⌘,），左侧为通用、动作配置、脚本管理。采用原生 macOS 设置窗口和公开 Liquid Glass API，关闭设置后菜单栏程序继续运行。

- 三种手势分别选择一个动作或「无」。初次运行全部为无，不产生未配置的系统操作；空绑定不弹动作气泡，按压缩罩保留。
- 每个动作名称最多 12 个计数单位，中文占 2 个单位。键盘/快捷指令的显示名称可修改，媒体使用操作名称，脚本名称同步用于绑定及气泡。气泡仅显示动作名称；运行状态和实际结果可在设置中查看。
- 键盘支持单键和组合键，点击录制后输入快捷键；测试时有 3 秒切换目标应用的时间。需要辅助功能授权，不自动授予系统权限。
- 多媒体支持播放/暂停、上一首、下一首、音量增减、输出静音。播放指令交给系统媒体路由；音量/静音要求当前输出设备支持对应软件控制，不代表麦克风静音。
- 双击绑定非空时自动开启，清空时自动关闭，`doubleClickEnabled` 自动同步为 `1/0`。开启后单击等待双击窗口；关闭后单击松开即判定。此字段由绑定管理，不再作为独立用户开关。
- 长按到阈值执行一次，松开不补发单击，长按为空也不会回退触发单击。配置变更从下一个完整手势生效。
- 保留低频操作冷却，被冷却忽略的手势不排队。暂停动作会保留当前设备模式和音频保护。

## 脚本

脚本管理支持新建、拖入/导入、重命名、复制、删除和导出。导入复制到脚本库，不修改原文件；界面提供只读源码预览；编辑通过「使用默认应用打开」交给系统默认纯文本编辑应用，找不到时回退到 TextEdit。智键不内置源码编辑器。外部保存后自动刷新，试运行和物理触发均读取磁盘上最新保存的内容；未保存的编辑不会执行。

运行设置支持 zsh/bash、工作目录、环境变量和超时。首版后台非交互运行，同时最多一个脚本，不排队重复启动；支持停止、退出码和限量标准输出/错误。打开外部编辑器不会触发智键的运行器；「运行」与动作「测试」会真实执行脚本。

名称、说明、绑定、运行参数保存在 `~/Library/Application Support/smartKey/actions.json`；脚本副本位于 `Scripts/<UUID>/script.sh`。导出的 `.smartkeyscript` 包包含内容与元信息，排除环境变量；普通 `.sh` 导出只包含内容。

详细运行语义、环境、版本恢复和源码扩展方式见 [动作开发说明](action-development.md)。

## 快捷指令

在「动作配置 → 选择动作」中选择「执行快捷指令」，展开列表选择本机快捷指令、设置显示名称和等待超时后保存。每次展开列表都会自动刷新；「打开快捷指令」仅启动系统快捷指令 App，无需先选择指令。绑定使用系统 ID，重命名不会改为执行同名指令；删除或未同步时保留原绑定，需刷新或重新选择。完整指令名称不受智键显示名称长度限制。

首版不传入额外内容，使用当前用户权限调用 macOS 自带的 `/usr/bin/shortcuts`。首次运行可能出现系统授权，交互式指令会等待用户输入。试运行会真实执行快捷指令。

同时最多一个由智键发起的快捷指令，重复触发不排队，与脚本各自独立。等待超时默认 300 秒，可设置 1–3600 秒；退出码 0 表示系统报告运行成功，错误详情可在执行结果中查看。停止等待、超时或退出智键只回收本地命令进程，快捷指令可能仍在系统中运行，必要时到快捷指令 App 检查。

## 设备与配置

布局与手势配置在 `~/Library/Application Support/smartKey/smartKey.conf`。首次启动若该文件不存在，会把当前出厂配置写进去；之后启动会把模板里的新键和注释合并进去，已有取值不覆盖（双击开关由动作绑定管理）。改完保存即热更新，不必重启。仓库根目录的 `smartKey.conf` 只作出厂模板。

- 启动检查已插入的内置 3.5mm 设备，同时监听后续插拔。检测到插入时，右下角先播放黑色遮罩动画，再延迟显示设备类型选择气泡；时长见 `insertionMaskDurationMs` / `insertionPopupDelayMs`。
- 每次启动检测到设备或重新插入设备都弹窗，不提供默认识别或隐藏设置。焦点落在上次确认的选项上（首次默认为智键，跨启动持久化），右上角仅显示倒计时数字；超时则按当前焦点项继续。超时见 `deviceChoiceTimeoutMs`。
- 选择「音频设备」时，如当前默认输出不是 3.5mm 耳机孔，则切换到该端口并读回确认；不独占、不响应智键线控。切换失败可重试。
- 配置音频输出前先排除 3.5mm 设备：仅剩一个可用输出时，跳过选择页并自动切换，读回确认后进入独占；多个输出时显示选择页，无可用输出时提示连接设备。自动切换失败或超时会返回选择页，等待用户重试。
- 音频选择采用系统原生「名称 / 类型」双列表格，设备列表随连接状态更新。列表不显示耳机端口，需选择内建扬声器、蓝牙、USB 等其他输出。点击「使用此设备」调用后端 `SmartKeyService.setDefaultOutput(uid:)`，读回确认后才调用 `setRemoteEnabled(true)`。这里使用现有 Swift 公共接口，无需额外网络端口；只修改默认音频输出，不修改输入设备。
- 切换失败、没有其他音频设备时保留音频选择页。HID 连接错误使用独立提示，区分设备占用、访问被拒绝和等待设备；等待超过 5 秒显示提示，但继续发现设备，迟到的设备仍可自动恢复。支持重试和取消，取消仅停用智键，不切回耳机孔，也不回滚已成功的音频切换。
- 配置成功且 HID 独占成功后才接收按键。独占对象为 `Transport=Audio` Consumer Control，键盘 / 蓝牙 / USB 媒体键不会误触发。
- 拔出设备立即释放独占、关闭提示并取消倒计时；再次插入重新选择。工作期间后端守卫监听默认输出：若被切到 3.5mm 耳机孔，立刻拉回本次运行记录的最后合法输出并保持独占；该设备已不可用或切换失败时，暂停智键并弹出音频选择页。首次选择智键时的输出页不变：无设备空列表、仅一台自动切、多台需确认。
- 菜单栏提供状态、「设置…」、「暂停/恢复动作」、「登录时打开」和「退出」。可在「设置 → 通用」切换设备类型。登录项注册仅对 `/Applications` 中的应用副本生效，首次启动会尝试注册（系统设置 → 通用 → 登录项）。手动重新配置不启动自动选择倒计时。
- 所有提示和遮罩优先显示在可用的内置屏幕，即使外接屏幕被设为主显示器。内置屏幕不可用时退回 `CGMainDisplayID()` 对应的主显示器，不跟随鼠标或前台窗口。
- 配置窗口使用固定的系统背景色，与原生列表和按钮保持一致，不依赖切换桌面时会更换合成策略的模糊背板。
- 不推断“拔掉智键后”的系统输出。首次配置时，当前或本次运行中记录到的非耳机孔输出仅用于预选，多个输出时用户确认前不切换；激活后切到耳机孔则由守卫静默拉回最后合法输出，不写入 conf。
- 气泡显示已绑定动作的短名称。下一次物理触发使用 `bubbleRetriggerMs` 冷却（默认 20 ms，冷却期内的触发直接忽略）；触发新动作时，旧气泡立刻从当前位置收回，新气泡正常出现。每个气泡独立动画，执行器不依赖气泡窗口创建成功。试运行不受物理手势冷却影响。
- 黑色遮罩只跟按下 / 松开，与气泡是否在场无关。
- 手势、插入动画、选择超时和配置窗口尺寸见用户 `smartKey.conf`。用户上次选择的设备类型不写入 conf，由程序单独持久化。
- 卸载：取消「登录时打开」，再把 `/Applications/smartKey.app` 移到废纸篓。

## 验证

`swift test` 覆盖设备选择与输出守卫、手势会话、绑定/配置恢复、脚本包、外部保存、脚本超时/取消/大输出/进程组清理，快捷指令列表解析、按 ID 执行、失败/超时/重复触发，以及设置页面渲染。默认测试使用模拟设备与临时脚本，不修改真实音频路由或独占硬件；渲染结果输出到 `/tmp/smartKey-*.png`。实际插拔、媒体路由、系统授权、锁屏/恢复和按键仍需设备验收，详见 [首版验证记录](v1-validation.md)。

如果系统默认选中 Command Line Tools 且找不到 `Testing` 模块，可使用已安装的完整 Xcode：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
```

HID 回归测试（先退出正在运行的智键，包括 `/Applications` 那份；会短暂独占内置 Audio 线控三次，不切换音频路由）：

```bash
SMARTKEY_HID_INTEGRATION=1 DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter realHIDCanRestartThreeTimes
```

本机对照验证：旧实现第一次启动为 `seized`，第二、三次为 `waiting`；新实现三次均为 `seized`，停止后均为 `idle`。修复采用每次新建 HID 管理器、`independentDevices` 下单独独占设备、初始枚举补取及 common run-loop 模式；按键物理动作仍需单独验证。
