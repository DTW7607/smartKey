# 智键产品方案与需求决策稿

版本：2026-09-07 · 状态：待产品决策，未批准开发

> 范围更新：用户已收敛首版为低频操作、统一动作接口、Liquid Glass 设置面板、键盘/多媒体/脚本绑定与脚本管理。当前首版以 [首版需求审查与建议](smartKey-v1-requirements-review.md) 为准；本文件保留为早期需求池，其快速连续操作指标及较宽首版范围不再适用。

本方案基于当前仓库源码与 README，辅以 Apple 官方文档核对平台边界。文中的优先级、参数、排期和指标均为建议，不代表已实现或已有用户研究结论。本次审查未运行应用、执行脚本或进行硬件实测。

## 1. 建议决策

将智键定位为：**一个可盲操作、低延迟、可自定义的 Mac 实体快捷键。普通用户选择动作即可使用，进阶用户可以连接自己的脚本。**

建议首版围绕“手势 → 绑定 → 执行 → 反馈 → 排障”形成完整闭环。动作覆盖媒体控制、键盘组合键、打开应用/文件/网址，以及后台执行自定义脚本。先支持一个全局方案，双击保持默认关闭。

产品核心价值是假设用户有少数高频动作，希望在不寻找键盘、不切换当前工作内容的情况下触发。需要通过试用验证；实体键的存在本身不等于用户会持续使用。

建议本轮先批准：动作基础架构、设置与绑定、键盘/打开类动作、受管理的后台脚本、权限与运行反馈；媒体动作先做兼容性验证，再冻结首版支持清单。把 Apple 快捷指令作为优先扩展候选。按应用自动切换、宏、持续按住、多设备和云服务暂缓。

## 2. 当前项目：可以复用什么，还缺什么

| 项目 | 代码确认的现状 | 对产品的影响 |
|---|---|---|
| 平台 | Swift 菜单栏程序；入口和安装包要求 macOS 26；Package.swift 声明 macOS 13 | 首版按 macOS 26 定义支持范围，统一声明；不能据包配置宣称支持 macOS 13 |
| 硬件接入 | 只匹配 `Transport=Audio` 的 Consumer Control，接收 usage `0xCD` | 目前是内置 3.5 mm 线控方案；USB、蓝牙按键及转接头不能直接纳入兼容承诺 |
| 手势 | 点击、双击、长按；应用双击默认关闭；出厂双击窗口和长按阈值均为 450 ms | 保留现有默认值作为试用起点，提供可视化调节和测试 |
| 判定时机 | 关闭双击时，点击在松开触发；开启后等待双击窗口；双击在第二次按下触发；长按到阈值立即触发一次 | 必须向用户说明延迟和互斥关系；长按并不是“松开才执行” |
| 底层事件 | 已提供 pressed/released，以及手势事件 | 有条件扩展持续按住，但目前没有按住动作的完整生命周期保证 |
| 动作 | `handleGesture` 只生成“点击事件”等气泡 | 尚无动作模型、动作绑定、系统操作、键盘注入或脚本执行器 |
| 连续操作 | `handleGesture` 通过 `nextGestureAt` 忽略冷却期间的手势；默认约 `1000 + 180 - 120 = 1060 ms` | 必须将动作执行与提示动画解耦，否则快速连续调音量等操作会丢失 |
| 设备流程 | 插入选择设备类型；选择非耳机孔输出并确认后独占；处理失败、拔插和恢复 | 已有接入基础，首版应优先复用 |
| 音频保护 | 激活后若输出转到耳机孔，会尝试拉回最后合法输出 | 新增“切换输出”动作须复用守卫约束，不能让两套逻辑互相争抢 |
| 配置 | conf 热更新、模板补新键、设备类型记忆 | 适合保留高级参数；动作绑定需要结构化持久化和普通用户可操作的界面 |
| 状态与登录 | 菜单栏状态、重新配置、退出；安装版首次尝试注册登录项 | 需要加入动作暂停、设置入口、执行状态；公开版应清晰表达登录启动选择和待系统批准状态 |
| 测试 | 主要覆盖设备选择、路由守卫、配置；有可选 HID 集成测试 | 未见专门的手势边界测试和动作执行测试；现有测试不能证明完整快捷操作可靠 |
| 分发 | 安装脚本为本机 ad-hoc 签名与复制安装 | 自用基础可保留；外部分发需单独设计签名、公证、升级与权限连续性 |

## 3. 用户与使用场景

| 用户/场景 | 希望完成的任务 | 推荐组合示例 | 验证重点 |
|---|---|---|---|
| 日常办公与听音频 | 快速暂停、静音，无需寻找播放器 | 点击播放/暂停；长按输出静音；双击可选下一首 | 系统媒体目标是否符合用户预期，输出设备是否支持调节 |
| 高频快捷键用户 | 把难按的组合键变成单键 | 点击自选组合键；长按另一个组合键 | 焦点、系统冲突、输入法、误触成本 |
| 开发者/自动化用户 | 一键运行自己已有的命令 | 点击运行检查脚本；长按打开项目 | 环境变量、并发、输出、取消与失败定位 |
| 演示者 | 不看键盘也能翻页 | 点击右方向键；长按左方向键 | 前台目标、全屏模式、现场可靠性 |
| 会议用户 | 快速静音/解除静音 | 绑定会议软件快捷键；以后增加专用适配 | 应用静音与系统输入静音不等价，不能错误显示“麦克风已静音” |
| 有操作便利性需求的用户 | 减少复杂键盘动作 | 较长的长按阈值、关闭双击、简洁反馈 | 按压力度属硬件问题；软件需支持可调时序、VoiceOver 和减少动态效果 |

首版优先服务前两类与脚本用户。演示可通过组合键自然覆盖。会议专用控制需要单独验收，不能因为能发送快捷键就宣传为可靠的全局会议静音。

建议先邀请 5–8 位目标用户完成真实任务试用，记录他们最常用的三个操作、每天使用次数、误触后果和设置困难。访谈用于调整优先级，不以未经验证的市场规模或功能数量代替需求证据。

## 4. 交互与产品规则

### 4.1 首次使用与日常操作

首次路径：启动 → 当前设备配置流程 → 展示“点击 / 长按 / 双击关闭”三张绑定卡 → 选择动作与参数 → 按需处理权限 → 测试 → 保存启用。

提供“媒体”“快捷键”“自定义”三种起步模板，但只有用户选择并保存后才生效。升级已有用户时保持未绑定或原有绑定，不静默新增动作。媒体模板建议点击播放/暂停、长按输出静音；具体支持范围以验证结果为准。

每张绑定卡至少展示：手势、动作名、目标/关键参数、启用状态、测试入口和错误提示。空绑定是合法状态，表现为“不执行操作”。双击关闭时保留其绑定但置灰，重新开启可恢复。

菜单栏增加“暂停动作 / 恢复动作”“设置…”和最近执行状态。建议暂停只停止动作分发，保留当前音频保护和线控独占，使按键不会意外变回系统媒体键；“释放设备/切换为音频设备”是另一个明确操作。暂停需在菜单图标和状态中持续可见。

正常按键反馈不抢焦点。动作配置页的快捷键测试采用“倒计时后测试”，允许用户切回目标应用；脚本测试会真实运行，按钮与预览应明确说明，不能把真实执行包装成无副作用检查。

### 4.2 手势规则

| 情况 | 建议行为 |
|---|---|
| 双击关闭 | 每个有效短按松开后触发一次点击，连续两次短按执行两次 |
| 双击开启 | 第一次松开后等待窗口；第二次按下在窗口内则仅发双击；否则发点击 |
| 长按 | 第一次按下达到阈值后执行一次，松开不补发点击，不自动重复 |
| 双击第二次按住不放 | 沿用当前规则：已发双击，不再发长按；测试页说明这一点 |
| 第二次按下恰在边界 | 用单调时钟和明确时间比较定义；建议间隔小于窗口才算双击，等于窗口视为新一次；加入确定性测试 |
| 长按期间拔出、休眠、禁用 | 清理未完成手势，不补发动作；恢复后等待新的完整按压 |
| 调整阈值/切换方案 | 当前按压沿用按下时的配置快照，新配置从下一次按压生效 |
| 重复 down、孤立 up、接触抖动 | 不重复执行；根据硬件测量增加必要的输入去抖，不能用气泡时长充当去抖 |
| 双击延迟期间前台应用变化 | 点击/键盘动作按按下时记录的目标验证；目标已经变化则取消并提示，避免发到新窗口 |

继续默认关闭双击。开启开关旁明确显示“点击将等待最多 450 ms 以判断双击”，并实时反映用户设定值。长按阈值也从 450 ms 起步，建议界面提供 300–1500 ms 调节范围和慢速预设；范围属于待试用验证的产品建议。

暂不增加三击、四击或“超长按”隐藏手势。新增手势会增加记忆成本与判定冲突；连续调节和按住说话应另立需求。

### 4.3 执行反馈

反馈要说明动作结果：例如“已发送播放/暂停”“音量 45%”“脚本运行中”“执行失败：找不到解释器”。仅在实际读回状态时显示“已暂停”“已静音”等确定结果。

将按压反馈、动作状态和提示动画分开管理。可以合并连续音量提示、限制气泡数量，但不得因此丢弃已经接受的动作。无可用显示器或气泡创建失败也不能阻止后台动作执行。

正常成功可关闭视觉反馈；错误仍保留菜单栏状态和历史入口。长任务显示运行中与取消入口，完成后提示一次。屏幕位置默认沿用内置屏优先，高级选项“主屏/鼠标所在屏”可后置。

## 6. 自定义脚本：首版应写清楚的契约

### 6.1 两种执行方式

| 维度 | 后台运行：建议首版 | 在终端中运行：建议 P1 |
|---|---|---|
| 适合任务 | 自动化、构建检查、启动程序、处理文件 | 需要输入、持续查看输出、交互调试 |
| 窗口 | 不打开终端，不改变焦点 | 新建专用终端会话，不向用户已有命令行盲目输入 |
| 输入 | 非交互；标准输入默认关闭 | 用户在 Terminal.app 中交互 |
| 成功定义 | 能取得退出码；0 表示进程报告成功，不保证外部业务结果 | 基础版只报告“已在终端启动”，不能直接报告“执行成功” |
| 管理能力 | 超时、取消、运行状态、有限日志 | 若无专用回传机制，不承诺完整退出码、终止或子进程追踪 |
| 默认选择 | 是 | 用户明确选择；首期不同时适配多种终端 |

“通过终端执行脚本”的底层需求通常是能运行命令行任务。后台进程也能满足这一需求，无需每次弹出窗口。如果用户确实需要输入或现场看终端，则必须选择可见终端这一独立需求。

### 6.2 配置与运行行为

首版提供两种输入：选择脚本文件，或填写命令文本。脚本文件显示完整路径，支持选择解释器；命令文本显式通过选定 shell 执行。直接运行可执行文件时使用程序路径与参数数组，不把所有字段拼成一条 shell 字符串。

| 配置项 | 建议默认与规则 |
|---|---|
| 显示名 | 必填，用于绑定卡、运行状态与历史 |
| 程序/脚本/命令 | 保存前检查文件存在、解释器可用；不能在保存时自动运行 |
| 解释器 | 命令文本默认 `/bin/zsh` 非交互、非登录模式；Python 等允许选择绝对路径 |
| 工作目录 | 脚本文件默认其所在目录；命令文本默认用户主目录；均在界面明示且可修改 |
| 环境变量 | 可增补；显示实际运行环境概要，不能假设 GUI 进程等同于用户的交互终端 |
| PATH | 给出受控默认值和显式覆盖；缺依赖时展示实际查找路径，不自动安装软件 |
| 用户 shell 初始化 | 不主动读取登录/交互配置作为默认行为；所选 shell 自身的启动行为需测试并说明 |
| 超时 | 建议默认 30 秒，首版允许 1–3600 秒；长驻服务管理不纳入首版 |
| 并发 | 同一动作运行中再次触发默认忽略并提示“正在运行”；不同脚本最多同时 2 个，满额时拒绝并提示，不积压历史点击 |
| 输出 | stdout/stderr 分开、持续异步读取；每路最多保留 256 KiB，超出后继续排空并标记截断，避免管道堵塞 |
| 取消 | 先请求终止，宽限约 2 秒后处理仍存活的受管进程；覆盖受管子进程，不承诺控制主动脱离进程组的守护程序 |
| 重试 | 默认不自动重试；用户从历史手动重试前可见动作名称和目标，防止重复提交或反复切换状态 |
| 变量 | 可提供手势名、触发时间、前台应用标识；作为参数或环境变量传递，不做未经转义的命令文本替换 |
| 编辑时运行 | 已开始的执行使用配置快照；修改从下一次触发生效 |

建议首版脚本采用“一次授权启用，后续按键直接执行”的产品体验，不在每次按键时弹出确认。用户主动新增或修改命令时展示内容并保存启用；未来导入的脚本绑定默认停用，经过审阅后再启用。

本地脚本以当前用户身份执行，能够产生当前用户权限范围内的文件与网络副作用；超时和取消是进程管理能力，不是脚本沙箱，也不能撤销已发生的副作用。首版不自动提权、不保存管理员密码，不把关键凭据写入动作配置或常规日志。需要交互式 `sudo` 的任务归入终端模式，不在后台一直等待密码。

脚本文件内容可能被外部编辑。首版明确这是“受信任本地文件引用”，不承诺文件内容每次运行前均被审查；含外来配置的导入、内容变更审阅或哈希固定可在 F24 中扩展。

### 6.3 退出、拔插和睡眠

暂停动作和拔出设备：立即禁止新触发、清空未执行任务；已经运行的有限时长后台脚本继续执行并保留取消入口，避免仅因拔插就中断文件处理。

锁屏：首版停止接受所有新动作，不在解锁时补发；正在运行的后台脚本按原超时策略继续。休眠前清理按键状态与未执行任务，唤醒后校验设备和超时任务。超时按真实经过时间计算，不在电脑恢复时重新给任务完整时间。

退出应用：如果有受管脚本运行，展示“取消退出 / 停止任务并退出”。强制退出与系统掉电不能保证清理已脱离管理的进程；下次启动将未完成记录标记为“中断/结果未知”，不自动重跑。交互终端会话由终端管理，退出智键不冒充已经停止其中任务。

## 7. 系统动作与权限边界

### 7.1 动作能力分层

优先使用可维护的公开能力；涉及非公开接口或 UI 自动点击的候选功能，不进入首版稳定承诺。动作元数据应标注“可读回结果”“仅命令已发送”“目标不支持”三种不同能力。

媒体播放/暂停：产品语义先定义为“交给系统媒体路由处理”，不承诺总能作用于用户主观认为的播放器。第一阶段测试原生播放器、浏览器音视频、无播放源和多源竞争。若公开实现无法达到稳定目标，决策选项是限定已验证的指定应用控制，或通过快捷键/快捷指令提供自定义入口；不得静默改成“按空格”。

音量和输出静音：针对当前默认输出，优先读回最终值。输出可能不支持软件调节，例如部分数字输出；遇到此类设备提示不支持，不改动其他设备或切换音频路由来掩盖失败。“输出静音”与“麦克风静音”在动作列表中完全分开。

键盘动作：只模拟配置的按键，完整发送 down/up，不连续读取用户输入。快捷键录制仅在显式录制期间进行。保存时提示可识别的冲突，但不能保证发现所有第三方应用冲突。前台应用、输入法、键盘布局与安全输入场景均需验收；不能保证应用收到组合键后一定完成预期业务操作。

打开类动作：应用已运行时可激活，未运行时启动；文件按系统关联打开。打开网址默认限制为普通网页协议；自定义 URL scheme 后置并明示将唤起的应用。路径中中文、空格和文件移动必须有明确处理。

Apple 快捷指令有官方命令行入口，可列出并运行已有快捷指令，适合作为 P1 扩展。官方也指出含输入请求的快捷指令会暂停等待输入，因此仍需要运行中状态、超时与手动取消。[Apple：从命令行运行快捷指令](https://support.apple.com/en-ca/guide/shortcuts-mac/apd455c82f02/mac)

### 7.2 按功能引导权限

| 能力 | 产品要求 |
|---|---|
| 控制电脑/模拟键盘 | 验证辅助功能授权需求；选择这类动作时解释用途，展示当前授权状态和系统设置入口 |
| 控制其他应用/Terminal | 按实际 Apple Events 实现处理自动化授权，按目标应用处理拒绝和恢复 |
| HID 读取 | 保留当前访问被拒绝诊断；通过干净环境验证真实所需权限，不把任意 HID 错误统一归为“缺输入监控” |
| 文件、脚本、截屏等 | 根据具体实现与访问对象处理系统限制；不在首次启动时统一索取所有权限 |
| 权限被撤销 | 仅阻止依赖该权限的动作，给出可恢复状态，其余能力继续工作 |
| 更新/重新签名 | 验证权限是否仍有效；失效时定位到具体动作，不诱导用户反复授权无关权限 |

macOS 的辅助功能控制与应用间自动化是不同授权路径，产品不能合并成一个“已授权全部系统操作”的开关。[Apple：允许辅助功能 App 访问 Mac](https://support.apple.com/en-gb/guide/mac-help/mh43185/mac)；[Apple：允许 App 自动化控制其他 App](https://support.apple.com/en-gb/guide/mac-help/mchl108e1718/mac)

### 7.3 隐私与可恢复性

首版本地运行，不需要账号或云端记录。最近记录建议最多 200 条或 7 天，先到即清理；默认只持久化动作名称/类型、时间、状态、耗时、退出码及错误摘要。stdout/stderr 默认仅在当前会话内限量展示，关闭或重启即清理；持久化详细输出作为主动开启的调试选项。

日志不默认保存原始键盘输入、命令全文、环境变量或敏感脚本输出；诊断导出先预览，移除用户路径和可能的敏感字段。用户可清空历史。配置恢复只恢复映射与设置，不宣称能够撤销脚本、发送信息或系统操作的效果。

## 8. 设置组织与配置模型

建议设置分为四页，而不是将所有能力放入一个长表单：

1. **按键动作**：三个手势、当前绑定、动作编辑与测试；未来承接方案选择。
2. **设备与手势**：当前状态、重新配置、双击开关、阈值与按压测试。
3. **运行记录**：执行中任务、取消、最近结果与诊断。
4. **通用**：登录启动、反馈开关、权限状态、配置恢复与版本信息。

沿用现有原生 macOS 风格和气泡反馈。动画参数仍放在高级配置，不要求普通用户理解布局常量。

建议动作配置使用独立、带版本号的结构化文件，例如 `actions.json`。保留 `smartKey.conf` 管理现有手势/外观参数，界面修改手势时通过同一配置服务写回 conf；同一个字段只设一个持久化来源，防止 UI 与手写配置争抢。

建议模型：`schemaVersion`、`actions`、`bindings`、动作执行策略；动作包含稳定 ID、类型、显示名、参数与启用状态。`profiles` 在确实批准多方案时再引入，首版只保留扩展空间，不开发隐藏复杂度。

保存流程：完整校验 → 生成新版本 → 原子写入 → 应用配置快照 → 保留上一有效版本。手写配置错误时继续使用上一有效版本并指明字段，不能默默恢复出厂动作。迁移不覆盖用户绑定，不把示例脚本自动设为启用。

未来批准按应用方案时，建议采用“明确暂停优先 → 手动固定方案 → 前台应用精确匹配 → 全局方案”的顺序；每个手势区分“继承全局”与“明确不执行”。在按下时确定目标和规则，并在实际执行前再验证目标，避免双击等待或排队时切换应用造成错发。

## 9. 工程拆分与现有代码衔接

建议保留接入与音频管理模块，在现有事件输出之后建立动作层，不让 AppDelegate 同时承担手势判定、进程管理和设置存储。

推荐数据流：

`HID / 插孔事件 → GestureRecognizer → BindingResolver → ActionDispatcher → 各类 Executor → 执行结果与反馈`

设备是否可用、暂停和锁屏状态在分发前检查；映射读取配置快照。执行器与 UI 不互相等待：脚本耗时不会阻塞键盘动作或设备状态变化。脚本使用有上限的并发；键盘动作在受控短队列中保持按下/释放顺序，过期或目标变更的动作直接取消。音量调整可以合并提示，但必须保留每一次有效增减的语义。

主要新增模块建议：

| 模块 | 责任 | 与现有工程的关系 |
|---|---|---|
| ActionDefinition / BindingStore | 动作结构、绑定校验、保存与迁移 | 新增；与 RuntimeConfiguration 分工 |
| BindingResolver | 手势到动作的选择、目标快照 | 接收 `SmartKeyGestureEvent`；必要时扩展事件时间和输入会话 ID |
| ActionDispatcher | 生命周期、状态门禁、并发和事件去重 | 从 `handleGesture` 独立出来 |
| System / Keyboard / Open Executor | 平台动作与能力探测 | 复用音频 API 时遵守 AudioOutputGuard |
| ScriptExecutor | 子进程、输入输出、超时与取消 | 独立于主线程和动画 |
| PermissionCoordinator | 各能力授权状态与引导 | 与设备连接错误区分 |
| ExecutionHistory / FeedbackPresenter | 真实结果与界面呈现 | 复用气泡外观，替换仅显示手势名称的逻辑 |
| Settings UI | 编辑、测试、状态与恢复 | 与现有设备配置页联通 |

不需要新增本地网络端口，也不需要账户服务。为未来硬件做轻量事件接口即可；尚未批准 USB/蓝牙支持前，不建设完整设备插件框架。

## 10. 验收与质量门槛

以下为建议目标，需在技术验证后确定测量方法和基准机，不能当作当前性能结果。

| 范围 | 首版验收条件 |
|---|---|
| 基本闭环 | 每类支持动作均能配置、测试、保存、物理按键触发、查看结果；重启后绑定一致 |
| 点击延迟 | 双击关闭时，从收到松开事件到开始调用本地执行器 p95 ≤ 100 ms；不把第三方响应或脚本总耗时计入该指标 |
| 双击/长按 | 阈值两侧与边界的确定性测试；同一手势最多分发一次；长按松开不额外点击 |
| 连续操作 | 双击关闭下，模拟 5 次/秒短按持续 10 秒，计数型测试执行器恰好执行 50 次；真实 HID 频率另行测量 |
| 动画独立 | 气泡未收回、反馈关闭、屏幕变化或提示失败都不丢失有效动作 |
| 脚本管理 | 成功、非零退出、文件不存在、解释器不存在、无读取/执行权限、超时、大输出、重复触发、取消与受管子进程均有测试 |
| 复杂路径 | 中文、空格、引号、不同 cwd/PATH 均正确传参；外部参数中的 shell 字符不会被意外执行 |
| 权限 | 全新授权、拒绝、撤销、重新授权；错误不阻断无关动作，不反复弹系统授权 |
| 键盘安全 | 中途暂停、拔出、取消、正常退出不遗留已模拟的修饰键；切换目标后不发往错误应用；不干扰用户自己按住的修饰键 |
| 状态恢复 | 覆盖按住拔出、双击等待时睡眠、运行中锁屏、恢复后 HID 重连；旧事件不补发 |
| 音频守卫 | 原有设备/路由回归通过；切换动作不选择被占用耳机孔，不产生来回切换 |
| 媒体效果 | 对每个宣称支持的播放器与输出设备验证；命令发送与可读回结果的文案一致 |
| 配置可靠性 | 畸形/部分写入配置不生效，用户旧配置可迁移，上一有效版本可恢复 |
| 可访问性 | 设置全程键盘可操作；VoiceOver 可读手势/动作/错误；减少动态效果与高对比度可用 |
| 稳定性 | 8 小时混合场景试用无崩溃、卡键、失控子进程；内存无持续增长；记录空闲 CPU/唤醒次数基线并避免高频轮询 |
| 真实硬件 | 每个承诺兼容的 Mac/按键组合至少 100 次混合手势及 20 次拔插/休眠恢复；记录漏触、误触和重复触发，出现重复或残留按键则不放行 |

验收矩阵至少覆盖：支持的 macOS 26 版本、计划支持的 CPU 架构、不同 Mac 内置插孔与实体键、内置/外接/合盖屏幕、扬声器/蓝牙/USB/HDMI 输出，以及键盘映射工具共存场景。只承诺实际测过的组合；不通过模拟测试推断转接头或另一种硬件兼容。

验证顺序建议：确定性单元测试 → 模拟执行器与进程集成测试 → 权限/界面人工测试 → 真实设备验收。开发中的普通测试不应抢占用户正在使用的真实设备或修改音频路由。

试用产品指标建议：首个动作配置成功率 ≥ 90%；中位首次成功时间 ≤ 3 分钟；支持范围内有效触发成功率 ≥ 99%；错目标/重复执行为零容忍缺陷。上述目标须明确样本量和失败分类；小样本通过仅代表发布检查，不足以证明长期故障率。七日持续使用、常用动作分布和误触反馈用于后续排序，首版可本地计数配合自愿反馈，不预埋默认上传行为。

## 11. 路线、依赖与粗略投入

假设：一名熟悉 Swift/macOS 的开发者，能持续获得真实按键和目标机器测试，复用当前视觉风格，范围为 macOS 26 单平台。以下为有效工作日估算，不含采购、证书办理、外部等待和需求变更；技术不确定性较高，不能作为承诺日期。

| 阶段 | 交付物 | 粗估 | 放行条件 |
|---|---|---|---|
| A：可行性与范围冻结 | 媒体路由、音量能力、键盘权限、后台脚本原型；确认手势时序 | 3–5 日 | 得到已验证的支持清单、权限表和不可用项替代决策 |
| B：动作内核 | 绑定模型、分发、提示解耦、基础执行器、脚本生命周期 | 7–11 日 | 端到端模拟测试通过，重入与取消可解释 |
| C：配置与产品闭环 | 设置页、测试、权限引导、运行记录、配置迁移 | 6–9 日 | 新用户无需编辑文件完成首个操作 |
| D：稳定性与内测 | 手势边界、系统恢复、硬件/应用矩阵、问题修复 | 5–8 日 | 第 10 节发布门槛达标，试用反馈支持首版定位 |
| E：公开分发（如选择） | 签名公证、安装升级、恢复、说明与支持清单 | 3–6 日 | 干净机器安装运行、升级保留配置与权限检查通过 |

内部可用版合计约 21–33 个有效工作日，即约 4–7 周；公开版另计分发阶段，且建议为平台/硬件不确定性预留 20%–30% 缓冲。实现 F16–F29 不包含在此估算中。

若预算不足，优先压缩媒体动作数量、打开类动作种类与高级外观选项；保留一项已验证媒体动作、组合键与后台脚本这三类价值入口，以及执行管理、错误反馈和状态恢复。仅配置文件的工程验证版可更早完成，但不作为普通用户首版。

对外发布建议采用 Developer ID 签名、公证与稳定应用标识流程；当前 ad-hoc 安装脚本仅作为本地开发用途。Apple 的公证流程针对分发软件进行自动检查，不能用“已公证”替代产品测试或 App Review。[Apple：在分发前公证 macOS 软件](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

商业模式、定价、渠道、量产硬件及售后保修暂不设定结论。若计划卖硬件套装，需另立产品线工作包：插头/电气适配、机械寿命、人体工学、兼容清单、包装说明、供应链与退换支持；这些成本没有计入软件排期。若只是自用工具，可后置商业化研究。

## 12. 风险与相应产品取舍

| 风险 | 早期信号 | 建议处理 |
|---|---|---|
| 450 ms 长按导致误触 | 用户短按被识别为长按 | 试用测量、阈值预设；不默认绑定破坏性操作 |
| 开启双击后觉得点击迟钝 | 用户重复按键或关闭功能 | 默认关闭、开关旁展示延迟、提供测试 |
| 系统媒体目标不确定 | 多播放器下控制了错误应用 | 明确系统路由语义，必要时限定支持应用 |
| 常见输出不支持调音量 | HDMI/USB 设备执行无变化 | 能力检测并解释，不能假显示成功 |
| 脚本在终端能跑但后台失败 | 依赖 PATH、cwd 或输入 | 明示运行环境、验证解释器、后台/终端模式分开 |
| 权限被拒绝或升级后失效 | 用户反复触发无效动作 | 独立状态与恢复入口，验证稳定签名策略 |
| 配置越来越复杂 | 用户不知道当前按键做什么 | 首版一个全局方案；多方案必须显示当前有效映射 |
| 3.5 mm 设备无法唯一识别 | 耳机与智键被混淆 | 沿用每次插入选择；自动记忆免询问须另立决策和证据 |
| 音频守卫与新动作冲突 | 默认输出来回切换 | 复用一套合法输出判定和切换确认流程 |
| 热更新改变手势语义 | 按住时配置变化造成意外动作 | 当前手势固定快照，后续手势再生效 |
| “暂停”含义不清 | 用户以为停止监听，实际只停动作 | 菜单清晰区分暂停动作和释放设备 |
| 脚本被误认为受限环境 | 用户运行不可信脚本 | 首次启用明示当前用户权限；导入不自动启用；不承诺回滚副作用 |
