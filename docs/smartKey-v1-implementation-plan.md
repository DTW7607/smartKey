# 智键首版开发计划

日期：2026-09-07。状态：首版代码与本地构建已实现，自动化验证通过；真实硬件、媒体应用兼容和完整系统权限/锁屏验收仍待完成。详见 [首版验证记录](v1-validation.md)。下文保留原计划与验收目标，不等同于所有人工验收已通过。

依据：用户已确定的首版范围及最新调整——脚本预览/编辑交给系统默认应用。本计划不包含内置源码预览、代码编辑、草稿或语法高亮；替代此前文档中的相应安排。

## 1. 首版交付范围

| 模块 | 首版交付 |
|---|---|
| 统一动作底层 | 动作定义、Provider 接口、注册、校验、执行状态、取消能力、统一分发；源码扩展示例 |
| 设置面板 | 原生可聚焦窗口；左侧通用、动作绑定、脚本管理；公开 Liquid Glass API 与系统动效适配 |
| 动作绑定 | 单击、双击、长按各绑定一个动作或“无”；名称 1–8 个可见字符；双击根据绑定同步 conf |
| 键盘动作 | 单键、组合键，含方向键、功能键及修饰键；显式录制、授权引导和测试 |
| 多媒体动作 | 播放/暂停、上一首、下一首、音量增减、输出静音；逐项验证支持范围 |
| 脚本管理 | 新建、拖入/导入、名称与说明、重命名、复制、删除、导出、默认应用打开、文件变化刷新 |
| 脚本执行 | 后台运行、试运行、状态与输出、停止、超时、防重复执行 |
| 气泡与恢复 | 展示动作短名称和状态；空绑定不弹气泡；保留低频冷却、设备配置和音频保护 |

当前规划默认：macOS 26、现有内置 3.5 mm 硬件、单全局方案、脚本使用 zsh/bash、后台非交互、同时最多一个脚本。这些是基于前次建议制定的实现默认值，后续变更需调整对应任务。

本轮不实现：宏、多步按键、持续按住、多方案、按应用自动切换、打开应用动作、快捷指令专用动作、交互式终端任务、自定义解释器界面、动态插件、跨平台及云同步。统一接口为新增类型保留入口。

## 2. 开发前固定的行为规则

### 2.1 动作与手势

- 动作短名按可见字符计数，去除首尾空格后 1–8 字；禁止换行/控制字符，兼顾输入法组合输入。
- 键盘/媒体动作自动生成名称，可修改；脚本名称作为对应动作名称，不另设绑定别名。内部均用稳定 ID 引用。
- 初次启用动作系统，三项绑定均为“无”；不凭现有手势开关自动新增系统操作。
- “无”不分发、不弹动作气泡、不新增冷却；按压缩罩与设备提示保留。
- 双击绑定非空则 `doubleClickEnabled = 1`，为空则写 `0`；无独立双击开关。字段由绑定管理，启动时修复派生值，保留 conf 其他用户配置。
- 缺权限或脚本暂时不可执行，不自动清空绑定，不暗中关闭双击。显式删除脚本并解除绑定时才同步关闭。
- 长按绑定为空时仍消费长按，松开不补发点击。双击关闭时，短按按单击规则处理。
- 保留现有低频冷却节奏，不排队重放被忽略的手势。冷却由统一分发策略执行，执行器不依赖气泡窗口。
- 当前按压/双击判定会话使用同一份绑定、时序和目标快照；配置变化从下一个完整手势生效。必须修正当前 `applyConfiguration` 在等待双击时可能立即补发单击的行为。

### 2.2 外部预览与编辑

脚本管理提供一个明确入口“用默认应用打开…”，旁边可显示应用名，并提供“在 Finder 中显示”。预览与编辑都委托给系统关联应用，智键不内置源码视图、不指定自己的编辑器、不修改系统默认关联。

使用 NSWorkspace 的公开 API 查找默认处理应用并打开文件；找不到处理应用、文件消失或打开失败时显示可恢复错误。Apple 的接口明确允许返回找不到应用/文件的情况，必须处理。[Apple：urlForApplication(toOpen:)](https://developer.apple.com/documentation/appkit/nsworkspace/urlforapplication%28toopen%3A%29-7qkzf)

默认处理应用不一定是编辑器。若目标是已知的终端/执行型应用，应在打开入口上如实显示该应用及可能执行文件的含义，不把操作标成“安全预览”，也不偷偷换成另一款编辑器。首版不尝试推断所有第三方应用的打开行为。

### 2.3 外部保存与实际执行

- 导入复制到应用脚本库；默认应用打开的是库内副本，源文件不被智键改写。
- 脚本名和内部路径分离，元信息重命名不移动脚本，避免破坏外部编辑器已经打开的路径。
- 智键只保存名称、说明、解释器、工作目录和超时等元信息。源码由外部应用保存，无“试运行草稿”概念。
- 监听目录与文件替换，并在回到应用时刷新；既覆盖原地写入，也覆盖编辑器的临时文件原子替换。
- 文件监听只用于更新状态，不能作为执行内容的唯一依据。试运行和物理触发都重新读取磁盘，形成本次执行快照，并记录内容摘要和修改时间。
- 外部应用未保存的内容无法读取；界面说明“运行磁盘上已保存的脚本”。打开完成不等于编辑完成，切回窗口也不代表已保存。
- 检测到读取中变化、正在写入、文件缺失或不可读时暂不启动，提示稍后重试，不静默回退旧缓存。监听去抖与读前读后检查是尽力检测，不承诺识别任意外部编辑器的保存事务。
- 已开始的执行不被后续保存改写；下一次触发读取新版本。快照方案须验证工作目录、相对依赖和 `$0` 等行为，并在脚本说明中明确约定，不能仅复制到临时目录就假设与源路径执行完全相同。
- 导出同样读取已保存磁盘版本，不导出外部应用中的未保存内容。

## 3. 模块边界与文件落点

现有 `SmartKey` target 继续负责 HID、手势、音频路由与设备状态。新增可测试的 `SmartKeyActions` target，负责动作领域模型、存储与执行；`smartKeyPopup` 负责应用组装、设置与反馈。动作 target 不依赖 HID，也不依赖 SwiftUI 视图；需要平台能力的执行器可使用 AppKit/CoreAudio。

| 建议文件/目录 | 职责 |
|---|---|
| `Sources/SmartKeyActions/ActionDefinition.swift` | 动作实例、参数版本、短名称、类型 ID |
| `Sources/SmartKeyActions/ActionProvider.swift` | 校验、能力、启动执行与状态/取消契约 |
| `Sources/SmartKeyActions/ActionRegistry.swift` | 按类型注册，未知类型兼容 |
| `Sources/SmartKeyActions/ActionDispatcher.swift` | 分发、来源策略、冷却与重复执行处理 |
| `Sources/SmartKeyActions/ActionStore.swift` | 动作/绑定/脚本元信息的版本化存储与恢复 |
| `Sources/SmartKeyActions/Executors/` | Keyboard、Media、Script 三类实现 |
| `Sources/SmartKeyActions/Scripts/` | 托管文件、导入导出、外部打开、变化监听与执行快照 |
| `Sources/smartKeyPopup/Settings/` | SettingsWindowController、通用、绑定、脚本页与 ViewModel |
| `Sources/smartKeyPopup/ActionCoordinator.swift` | 将设备门禁、手势会话、配置同步、权限反馈接入动作服务 |
| `Sources/smartKeyPopup/ActionFeedbackPresenter.swift` | 短名称、状态、气泡生命周期与菜单状态 |
| `Tests/SmartKeyActionsTests/` | 动作、存储、脚本运行与 Provider 集成测试 |

修改现有文件：`Package.swift` 注册 target；`App.swift` 只负责组装和转发；`RuntimeConfiguration.swift` 增加保留其他键的受管字段写回；`GestureRecognizer.swift` 与必要事件结构增加会话一致性；`GestureBubble.swift`/内容视图支持动作名称与状态。

同时检查 `GlassBubble.swift` 和 `PopupPanel.swift` 的动态私有选择器调用，迁移为公开接口。新设置窗口使用标准 NSWindow/SwiftUI 分栏，不沿用提示面板伪造焦点外观的机制。

以上为规划路径，实施时可按实际依赖微调；不得为减少文件数量把进程管理和持久化重新堆入 AppDelegate。

### 建议存储

用户 Application Support/smartKey 下保存：

- `smartKey.conf`：现有手势/外观参数；双击开关作为受管派生字段。
- `actions.json`：`schemaVersion`、动作实例、三个绑定、脚本元信息；作为唯一权威配置记录。
- `Scripts/<scriptID>/script.sh`：外部应用编辑的托管脚本，名称改变不改路径。

运行快照与限量输出使用独立临时/缓存位置。名称、说明不嵌入用户源码，因此重命名与说明修改不触碰源码。

元信息采用原子写入和上一有效版本恢复。conf 与 JSON 无法天然跨文件原子提交：先持久化权威记录、整体更新运行时，再同步派生字段，失败时显示待同步并在重启时修复，不能向用户展示虚假的全部保存成功。脚本导入/删除通过暂存、校验、提交及引用检查避免悬空引用。

## 4. 分阶段编写计划

每阶段形成一个可评审的变更单元，完成对应验收后进入下一阶段；不以“界面完成”代替执行链路完成。

### P0：工程基线与技术验证（2–3 日）

工作：

- 记录现有构建、测试、设备/音频流程基线；保留当前工作区已有改动，尤其不覆盖用户的 `smartKey.conf` 修改。
- 检查 Swift 工具链、SDK 与平台声明，统一实际 macOS 26 支持口径，避免只改 manifest 却与工具链不兼容。
- 验证键盘注入及授权路径；逐项验证六类媒体操作的公开实现、系统媒体路由和输出设备能力。
- 验证默认应用查找/打开、外部编辑器原子替换保存，以及执行快照与脚本路径语义。
- 验证公开 Liquid Glass 组件、标准设置窗口焦点、旧气泡私有调用替换方案。
- 确定三页的信息布局和空/加载/不可用/错误状态，作为后续实现依据。

交付：技术验证记录、受支持动作清单、权限表、快照语义、页面状态说明。

放行：每个首版动作都有可维护实现；无法保证的媒体动作需列出具体限制和处理方案，不静默删除或用按空格等行为代替。任何必要技术障碍在本阶段暴露。

### P1：统一动作内核与配置（2–3 日）

工作：

- 实现 Definition、Provider、Registry、Dispatcher、执行句柄与标准错误结果。
- 类型使用可扩展 ID 与参数版本，避免把所有新类型散落到 UI/HID 的 switch 中。
- 实现动作短名称、三手势绑定、空绑定及持久化校验。
- 建立配置服务，推导并写回双击开关；实现错误恢复与文件监听自写抑制。
- 实现手势会话快照与冷却策略；接口层可用假执行器独立测试。

交付：无需 UI/HID 即可运行的动作服务，绑定保存后可重启恢复。

放行：一个已接受事件只执行一次；空绑定不执行；双击联动与写入异常测试通过；注册测试 Provider 不改手势代码。

### P2：脚本库与外部编辑链路（3–4 日）

工作：

- 实现新建、单文件拖入/导入、元信息编辑、重命名、复制、引用检查与删除。
- 导入时复制托管文件，校验名称/类型/路径；不运行、不自动绑定。
- 实现默认应用打开、Finder 定位、失败反馈；没有内置源码预览、编辑器或草稿。
- 实现目录监听、外部保存刷新、恢复前台刷新、缺失/不可读状态。
- 实现每次执行/导出前的磁盘读取与快照服务。
- 导出普通脚本文件及包含元信息的版本化脚本包；不打包外部依赖或敏感环境变量。

交付：独立可测试的脚本库服务与元信息 ViewModel；即使没有设置页，也能验证完整文件流程。

放行：导入来源不改写；外部修改可发现；原子替换后继续监听；重命名不改外部打开路径；被引用脚本不能留下悬空绑定。

### P3：三类执行器与运行管理（4–6 日）

工作：

- Keyboard：单键/组合键、完整 down/up、目标快照校验、权限反馈，不遗留模拟修饰键。
- Media：落实 P0 验证的播放控制、音量与输出静音；可读回与仅发送的结果明确区分；复用现有音频约束。
- Script：选定解释器、显式 cwd/PATH、磁盘内容快照、后台非交互进程。
- 实现 stdout/stderr 异步排空与截断、退出码、30 秒默认超时、停止与受管子进程清理。
- 全局最多一个脚本运行；物理触发与试运行共享运行锁，不排队、不自动重试；其他动作不阻塞主线程。
- 完成暂停、拔插、锁屏/休眠、退出时的动作生命周期规则。

交付：三类动作均可通过统一入口执行、取得结果和定位错误。

放行：脚本大输出、非零退出、超时、取消、重复触发、缺文件/依赖均有结果；试运行与物理触发不会走两套执行代码。

### P4：原生设置面板（3–4 日）

工作：

- 新增菜单栏“设置…”和标准设置快捷键；建立单个可聚焦窗口，关闭不退出应用，恢复上次页面。
- 通用页：设备状态/重新配置、登录启动、暂停动作、时长、权限入口；双击为只读自动状态。
- 绑定页：三个手势、分类动作选择、“无”、短名称、参数编辑；键盘录制和倒计时测试。
- 脚本页：列表与元信息详情、拖入区域、默认应用打开、导入导出、重命名/删除、试运行/停止、结果。
- 使用原生侧栏、工具栏、分组控件与公开玻璃效果；加入状态切换、拖入高亮等必要动效。
- 完成空库、全空绑定、权限不足、文件消失、运行中、失败、未保存元信息等状态。

交付：用户不编辑 conf、不改代码即可完成配置；脚本内容始终交给默认应用。

放行：全程键盘可操作、焦点正确；无隐藏占位功能；控件能真实触发前面阶段的服务；原生玻璃与系统辅助设置协调。

### P5：手势、气泡与应用集成（2–3 日）

工作：

- 将现有 `handleGesture` 接到 ActionCoordinator/Dispatcher，气泡显示实际动作名称。
- 完成无绑定不弹窗、低频冷却、双击自动开关及长按为空不回退单击。
- 将运行状态接到气泡与设置结果，失败原因可查看；提示不抢用户目标窗口焦点。
- 迁移气泡/面板私有调用到公开接口，保持现有视觉意图并记录可见变化。
- 处理屏幕变化、设备重配置、运行中脚本更名/保存、解除绑定和退出。

交付：物理按键到真实动作、短名反馈与运行记录的完整闭环。

放行：设备/音频守卫流程回归通过，脚本执行不被气泡生命周期终止；动作名称与触发快照一致。

### P6：回归、硬件验收与交付文档（3–4 日）

工作：

- 执行第 5 节验收矩阵并修复发现的问题；不引入高速连击吞吐量目标。
- 检查原生窗口尺寸、浅深色、减少透明度/动态效果、增加对比度、VoiceOver、键盘导航。
- 检查内置/外接屏、不同合法音频输出、睡眠恢复、权限拒绝与重新授权。
- 构建安装包，在明确测试环境验证启动、旧配置迁移、登录项与重启恢复。
- 更新 README、脚本运行约定、支持范围、排障说明、动作扩展示例。

交付：首版可安装构建、验证记录、已知限制与开发扩展说明。

放行：所有约定首版动作在支持范围内验收通过，无卡键、意外重复执行、错误目标执行、文件内容被误覆盖等阻断问题。

## 5. 验收矩阵

| 编号 | 必测场景 | 通过条件 |
|---|---|---|
| A01 | 新装、全空绑定、重启 | 不触发未配置动作；无对应气泡；设备模式稳定 |
| A02 | 三手势分别绑定与清空 | 动作和名称正确；清空即时持久化，无旧动作残留 |
| A03 | 双击联动/手动 conf 冲突/写入失败 | 权威绑定与运行时一致，派生字段可修复，UI 不虚报保存成功 |
| A04 | 按压中改绑定，双击等待中关双击 | 本会话语义固定，无意外补发或错绑 |
| A05 | 长按为空 | 松开不补发单击；黑色按压反馈仍正常 |
| A06 | 名称中文/英文/组合字符/输入法/超长 | 1–8 字规则统一，界面、持久化、气泡一致 |
| A07 | 键盘权限、焦点变化、物理修饰键共存 | 正确发送与释放；不发往错误目标，不干扰用户自己的按住状态 |
| A08 | 多媒体多源与不同输出 | 作用范围可解释；不支持设备明确失败；不改变音频守卫约束 |
| A09 | 拖入/默认应用打开/外部保存/试运行/绑定 | 端到端可用；导入来源文件保持原内容 |
| A10 | 原地写入、原子替换、只改未保存草稿 | 前两者执行最新磁盘内容；未保存内容不生效，文案清楚 |
| A11 | 打开应用失败、外部删除、读取中变化 | 有错误状态和恢复入口，不运行旧缓存或虚报已更新 |
| A12 | 运行期间再次保存/重命名 | 本次运行保持快照，下次用新内容；运行记录名称不被追改 |
| A13 | 导出/重新导入/被引用脚本删除 | 文件与元信息往返正确；解除引用后双击同步关闭 |
| A14 | 大输出、超时、停止、重复运行、缺解释器 | 不阻塞 UI，不重复执行，结果和退出码可检查 |
| A15 | 拔插、休眠/唤醒、锁屏、退出 | 清理旧手势，不补发；脚本按约定结束或保留状态 |
| A16 | 标准窗口与系统辅助设置 | 所有实际状态可读、可操作，动效/透明度正确降级 |
| A17 | 新增最小 Provider | 注册后可经统一分发器调用，不修改 HID/气泡内部逻辑 |

自动化测试优先覆盖时序、跨文件配置恢复、脚本 I/O/进程生命周期和外部文件变化，不为每个视觉控件编写镜像式测试。媒体、键盘、权限及 Liquid Glass 仍需真实系统验收。

测试使用临时配置与临时脚本。默认测试不抢占真实 HID、不修改真实音频输出、不执行用户脚本；硬件集成在专门测试步骤中运行。

实施验证命令基于现有项目：`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test`，以及 release 构建。运行前确认本机 Xcode 路径；本次制定计划没有运行构建或测试。

## 6. 交付切分、估算与风险

按一名熟悉 Swift/macOS 的开发者、有真实硬件可测估算，P0–P6 合计 **19–27 个有效工作日，约 4–6 周**。建议为平台权限、媒体实现和公开玻璃效果的兼容问题预留约 20% 缓冲。这是计划估算，P0 后重新校准，不等同于承诺日期。

建议依阶段拆成七个可评审提交/PR；一个阶段较大时再拆成模型、执行与界面几个内部提交。每个阶段应说明最终行为与验证，不混入未批准的新动作类型。

三个主要进度风险：

1. **媒体控制可维护性**：必须先证明可行，不以私有 API 或模糊的快捷键模拟掩盖支持缺口。
2. **外部编辑与执行一致性**：不能依赖编辑器退出通知或单一文件 inode 监听；尤其需要验证原子替换、未保存草稿和快照路径语义。
3. **旧玻璃效果迁移**：现有私有焦点/材质调用不只在一个文件中；迁移涉及外观变化与窗口行为，需真机对照。

首版交付按本地安装/内测构建规划；Developer ID、公证、自动更新和公开发行流程另立发布任务，不把当前本机安装脚本直接称为正式分发方案。

本次只制定并同步文档。开始编写时从 P0 进入，先完成可行性验证和页面状态说明，再按依赖顺序实现。
